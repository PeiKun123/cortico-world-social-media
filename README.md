# 社交视窗 · Cortico World

让 Bot 带着兴趣出去看看，也能自然接上评论区的话。

社交视窗把视频阅读、公开交流和记录放在一处：搜到感兴趣的视频，读字幕、看带时间标记的采样画面，接住回复与 @，或在合适的楼层聊两句。开启闲逛后，Bot 可以在空闲时自主探索；配置特别关注后，也能优先留意主人的近期作品和评论区。

**沿用你已有的 Persona、模型与 Memory，无需额外配置第二套模型。** 自主阅读、思考和发言仍会正常使用现有模型并消耗对应额度。 目前接入 B站，并提供默认关闭的抖音、快手实验适配；平台能力不同，详见下表。

| 你想做什么          | 社交视窗提供什么                                   |
| ------------------- | -------------------------------------------------- |
| 给 Bot 一个视频链接 | 详情、可用字幕、评论楼层与可选画面采样             |
| 让它有空自己逛逛    | 四档参考活跃度、分平台额度、按兴趣阅读与自主接楼   |
| 照顾自己的作品      | 本地指定主人账号，近期作品参与状态与评论区机会     |
| 看它到底说了什么    | 按视频折叠的互动时间线，保留楼层入口和实际发送回执 |
| 随时收住节奏        | 阅读、通知、公开发言、闲逛与特别关注分别开关       |

**开始前**：Cortico ≥0.2.5（World API 6）、Node.js ≥22.16；评论与通知需扫码登录自己的B站账号，默认网页发评需要本机 Chrome 或 Edge。画面采样另需 FFmpeg；没有 FFmpeg 仍能读详情、字幕和评论。无需 Browser World、Python 或单独的模型服务。发布包不含任何预绑定账号和个人记录。

## 0.6.3 · B站动态与主动 @

在World「配置 → 哔哩哔哩 → 动态与主动 @」单独开启所需能力，公共包默认关闭新权限。基础区仅放读取、发布、自主动态及@权限开关；额度、间隔和时段在默认折叠的「高级设置 · 动态频率与 @」中调整。

- **动态读取**：可读已登录账号的关注流、特别关注或指定UID的首屏动态，也可读取完整动态链接。每次最多五条、有总文字预算，记录原始编号、作者、正文、图片数量与可核实的评论目标。缓存按Bot账号隔离，在「平台与记录」折叠查看。默认每日20次，失败尝试也计数；不后台额外轮询，读取后立即退出本次浏览器。
- **主动 @ 特别关注**：默认关闭，当前仅支持显式选择的接口发评实验路径。Bot在prepare中选择mentionFocus后，World从本地绑定取UID、核对官网名称，并把@对象绑定进发送凭据；不会按评论者自称主人修改，也不会每条自动@。默认每天最多3次，普通发送间隔与防重仍保留。平台受理不代表对方一定收到提醒；此能力尚未完成真实通知到达验收。默认网页发评不会悄悄切换成接口。
- **海外客户端登录备用入口**：扫码不兼容时，可在「连接选项」打开独立B站官网窗口，自行登录，再点击“完成B站网页登录”。只有官网核实账号与Cookie中的UID一致才保存；不把密码、验证码或Cookie交给模型。这个入口支持bilibili.com的网页登录流程，**不代表支持Bstation／bilibili.tv账号**；海外App扫码兼容仍需按具体版本验证。

**空闲时主动动态**：开启后，默认每天最多主动1条、机会间隔6小时、安静空闲20分钟、Bot时区9—23点；均可在高级设置调整。待回应评论、QQ／Dungeon／群聊消息及正在进行的闲逛优先。World只提供可放弃的机会，不强制凑文案；沿用现有Persona；机会会唤醒现有Bot并产生正常模型用量，不另开一个模型，也不读取私聊补文案。机会、次数及账号绑定随记录保存，重启不会重置。自主动态仍受动态总量约束。

**纯文字动态发布**已加入，默认关闭。在同一“动态与主动 @”分区开启后，Bot先prepare保存账号、正文及可选的主人@标记，再用draftId从官网发布；每条最多500字，默认每天3条、间隔300秒。原生富文本@会核对准确UID。发送记录按账号保存，“已受理”与“公开可见 / 通知送达”分开说明；超时或重启后结果不明则保留记录并暂停新发布，不自动重试。明确未提交的失败可以重新prepare，已有回执或结果未知不能补发。已受理和结果不明占用每日发布份额，明确未提交的失败不扣份额，但仍保留记录及重试间隔。发布使用一次性的内存浏览环境，保留原网页草稿，任务结束关闭浏览器。发布记录最多2000条，达到保护上限会暂停而不删防重凭据。暂不支持图片动态、转发及私信收发。动态评论及楼中楼使用原生网页组件：先读取原动态取得准确链接和评论target，再prepare、publish。不会猜楼层，也不会同时转发为新动态。接口实验路径不保证公开展示。这里的“动态”与视频评论记录分别展示，避免把读到的动态误写成已发布内容。

B站详情、字幕、评论与通知本来就在使用接口；公开评论可在配置中选择官网评论框或接口实验方式。没有证据证明API发评必然仅自己可见，也没有通用参数能保证公开。账号、内容、会话状态及平台审核都可能影响结果；以单条发送回执和可见性核验为准，不换接口反复补发。

特别关注采用有限范围轮询，不是每条新评论的实时推送。三个平台都须分别登录和授权发评；返回评论编号仅代表平台受理，不能保证其他账号可见。遇到登录失效、验证或目标核对失败会保留原因，不自动重复提交结果不明的评论。

## 抖音群聊（本地实验）

在抖音配置展开「群聊监听」，分别开启监听及发言；填写 群号|准确群名，多群用分号隔开，保存后检查连接。官网不提供可靠的群号搜索，因此首次需群名，并固定唯一群聊的真实会话与Bot账号；同名或身份变化时暂停发送，不按名字猜测。换号或改群名可从本地配置预览本次检查结果后重新绑定，旧记录归档保留。默认名单为空，不含开发者的私人群。

默认每60秒检查新消息；提供安静、均衡、活跃三档，活跃档不要求@才接话。同群新消息合并投递并限制文字量，超过15分钟的消息只保留作上下文，连续失败按间隔逐步退避（最多15分钟）。首次历史只作上下文；由现有Persona判断是否接话，不逐条询问主人。群聊使用专用工具与记录，不能复用QQ、Dungeon或视频评论的发送凭据。重启保留记录；发送结果不明时不自动重发。平台返回编号只代表受理，尚无独立的其他成员可见性验证。主Persona思考上下文仍共享，目标隔离不等于完全独立的人格会话。

默认开启「抖音任务结束立即释放浏览器」：读取、回复或群聊检查结束即退出后台进程，登录资料保留；群聊仍按原间隔重新启动轮询。需要降低冷启动等待时可关闭该选项，此时群监听期间保留连接。快手普通群聊暂未接入，不提供伪装的监听开关。

## 抖音实验接入（0.7.0-beta.8）

抖音默认使用无窗口Edge在后台运行，保留登录态与官网交互；需要登录或人工验证时从配置主动打开窗口，不会自动切回有窗口模式。平台与记录的“全部”包含已接入平台已保存的发言和通知，按各自平台标识。

在配置页启用「抖音（实验）」，即可把完整官网视频链接或视频编号交给 Persona。使用本机独立 Edge，找不到时再寻找 Chrome；无需 Browser World 或远程调试。发送使用独立的干净页面，避免遗留草稿或回复状态串入下一次操作；默认任务结束立即关闭，关闭此选项后才按原空闲策略复用。抖音和 B站分别开关、分别保管登录资料。

| 能力               | 抖音范围                                                                                           |
| ------------------ | -------------------------------------------------------------------------------------------------- |
| 视频、图文与评论   | 从官网实际返回的作品文案、评论和准确编号读取；未登录时评论可能受限，读取不到会说明原因             |
| 楼中楼             | 保留主楼与子回复编号，可展开线程并回复具体的人；同名同文也按编号区分                               |
| 检索               | 首屏实验支持，不假报完整搜索或翻页                                                                 |
| 画面               | 在官网目标播放器采样；排除占位视频，未听音轨，不等于完整观看                                       |
| 推荐流             | 自动翻到下一条真实视频，沿用闲逛阅读与发评额度                                                     |
| 特别关注           | 单独填写主人抖音号或完整用户主页，保存后精确搜索并固定身份；与B站设置独立                          |
| 完整字幕、通知监听 | 暂未接入                                                                                           |
| 公开评论           | 默认关闭的实验能力；复用整理、额度和防重，以实际发送回执记录受理结果，未核实访客可见时不声称已公开 |

抖音与快手使用相同的连接布局：启用及发评权限开关即时保存，参数按平台单独保存。浏览器会按需启动、空闲自动关闭，running=false本身不表示故障；返回旧回执也不代表再次发评。unknown只表示结果待核实，不作为工具失败；同一位置的未核实记录不会因换文案或编号而重投，sent仍只表示平台受理。主人号已识别但作品列表未取得时，会显示「作品检查未完成」，不假报正在正常监测新评论。

需要登录时，在配置页点击「打开抖音登录窗口」，自己完成官方扫码或验证，再点击「完成抖音登录」。凭证只由官方页面写入本机部署的 data/socialmedia/douyin-browser-profile，不从日常浏览器复制账号。关闭登录窗口保留本机登录资料，不能视为退出账号。勿把验证码、密码或Cookie发给模型。

抖音只采用官方网页动作，不重放签名接口；遇到验证码、限流或发评目标不能唯一核对时停止本次操作。平台返回评论编号也仅表示受理，未核验前不会声称别人已经看到，不自动重发。

关闭实验平台即可继续原有B站流程。如需回退，尚未归档时可在扩展管理中选择 cortico-world-social-media@0.6.2，保留部署数据。已归档时须先完整恢复较早记录再回退，勿删除数据库或登录资料。

主人作品下的普通接话、问题、表情以及主人本人的评论均可结合上下文考虑回应，但只覆盖本平台实际支持并已核实的作品类型；受官网限制没有读到的内容不会假装已看见。各平台的“也考虑已有未回复评论”默认关闭，开启后可在已读取的主人作品范围内补看旧评论。待回应通知先获得处理机会，未处理条目在空闲时适度恢复提醒；临时问题可延后考虑，不丢记录，也不重复提交已有发送回执的位置。

## 三平台闲逛与放养

B站、抖音、快手分别使用自己的闲逛等待和额度，共用一个活动轮次，轮流获得机会。顶部只保留闲逛总开关与状态，活跃度统一在平台卡内选择轻量、均衡、活跃或放养；总开关与各平台开关均须启用。旧统一默认值继续兼容，界面不再重复提供一套全局额度编辑，不会自动替用户开启放养。

放养取消阅读轮数、视频/评论阅读数量和活动轮次时长限制，只等待空闲与两轮间隔；仍保留单次网络超时、公开发言权限/配额、同一人五条限制以及图片和存储预算。首次投递但未开始的机会仍会到期释放，避免永久占住轮次。

QQ或Dungeon新消息到来后，让当前已经开始的读取或发送完成，先保存读取结果与发送回执，然后停止后续闲逛步骤并回应新消息。World不会取消或重投进行中的评论；交接信息只记录进度，不把外部内容变为操作授权。

放养仍使用有界轨迹：每轮保留最近100条阅读详情，交接与面板默认只取最近10条和累计数量；这只压缩展示，不限制继续阅读。平台每日计数独立持久化，近期轨迹压缩和重启不重置当天额度。

## 主人评论区自动回应（各平台独立，默认关闭）

在特别关注中填写主人账号后，可选择「自动回应主人评论区的新评论」，保存会同时开启该平台的特别关注，仍须开启World、本平台和公开发评总开关。默认每2分钟检查，允许自定2—60分钟；首次对每件作品建立旧评论基线，不批量补评历史。它读取配置范围内的近期作品，每次检查最新作品和轮换作品、最多三页评论；不是全站实时推送，未返回或未覆盖的评论可能遗漏。

新评论进入持久待回应队列，由当前Persona理解并自然回应，不逐条询问主人。危险诱导与无意义资源消耗仍跳过；主人作品评论自动回应单独计账，不占普通发布、通知或闲逛额度，也不设单人次数上限；发送间隔、防重、账号核对和安全判断继续生效。关掉开关停止自动触发。普通偶尔捧场仍使用原有单独额度。

## 快手实验接入

快手使用独立Edge登录资料，与B站和抖音分别启停。默认无窗口后台运行，配置页可以主动打开登录窗口；只通过官网登录态和正常网页请求读取，不复制日常浏览器凭证或构造签名。登录资料保存在部署data/socialmedia/kuaishou-browser-profile。

| 能力                     | 当前范围与限制                                                                                                                           |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 账号、普通视频详情和评论 | 已用真实账号只读验证；评论保留准确编号与时间                                                                                             |
| 检索与推荐               | 读取官网返回的首屏候选；推荐元数据不等于看过画面                                                                                         |
| 特别关注                 | 可填主页或快手号，快手号核对官网号码字段；账号与额度独立                                                                                 |
| 图文                     | 电脑官网可能提示「暂未支持显示图片作品，请在移动端查看」；准确链接有时可单独读取评论；当前不支持图文自动发评或完整图文监测               |
| 主人作品列表             | 只采用官网实际返回的作品；列表未取得明确报错，不能解释为账号没有作品，也不能承诺覆盖图文                                                 |
| 发评与回复               | 顶楼评论走官网原生评论框，楼中楼仍为实验接口；均核对账号、作品和目标；楼中楼的他人可见性尚未完成验收；平台受理不保证公开展示，不自动启用 |
| 普通群聊                 | 未接入；不能监听群消息或向群内发言，不提供无效开关                                                                                       |
| 画面、字幕、全站通知     | 暂未接入；子回复通过官网独立接口有界读取，主楼和子回复编号分别保留；空结果不能证明发送失败或公开不可见                                   |

快手接入不依赖Browser World。遇到不支持的作品、登录验证或目标不完整会明确返回，不换推荐视频冒充目标、不自动重发。仍可关闭快手继续使用B站和抖音；三平台的功能范围以本页速查表为准，不能按B站能力推断快手也具备相同功能。

## 观察与资源（本地试用）

默认文字优先：围绕某人的观点或普通交流，可读原评论、父楼与必要上下文；主动评价作品或回答依赖画面的问题时，仍须补足作品信息，不能根据评论猜视频内容。可以在配置关闭文字优先，改为按兴趣选择画面观察，预算始终生效。

配置页「观察与资源」提供用量、保存和清理入口。低频容量选项折叠在「容量与保留策略」中：

| 项目            | 默认值与行为                                                                                                                                                      |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 画面采样        | 每次最多2帧、每天20次观察；缓存再次查看与失败尝试也计数，跨重启保留                                                                                               |
| 图片限制        | 每张最多512KB，超出不交付；视频下载限64MB，流式落盘，单次观察串行执行                                                                                             |
| 本World图片缓存 | 最多200MB、保留7天；同作品与采样点复用原图并注明采样时间，启动、定期和采样时维护                                                                                  |
| 累计图片交付    | 默认512MB，自资源记录启用后保守累计新图片字节；达到后继续文字交流。清理缓存不重置此预算，不把它当成宿主的实际附件用量                                             |
| 浏览器网络缓存  | 参考上限128MB，浏览器自行执行；默认在本进程首次访问及之后隔日清理网络缓存，也可手动请求，未运行时留待下次普通访问；保留Cookie与登录资料，不承诺整个登录目录硬限额 |
| 近期发言        | 90天或参考2000条，保护最近48小时、待处理关联和结果不明的记录                                                                                                      |
| 历史归档        | 更早的完整发送记录进入World自己的history.sqlite，按操作与目标检索防重，面板按需加载较早发言；达到默认512MB归档预算后暂停新增公开发言，不自动删除历史              |

第一次归档成功后，主记录升级为格式2，新版本可正常读取；旧版World会保护性拒绝读取，避免降级后失去防重信息。降级须先完整恢复归档，不能直接删除history.sqlite。

旧设置没有新增字段时自动使用默认值；既有maxFrames设置保留，新安装默认2帧。归档使用Node内置SQLite，不要求额外数据库服务；部分Node版本可能显示其SQLite实验性提示，实际归档与恢复有回归覆盖。

临时下载与解码位于本部署socialmedia/resource-cache的有归属标记工作目录，结束即清理。异常退出残留仅在足够旧、原进程已退出且路径无目录链接时回收；不扫描删除其他应用的临时文件。

**Cortico历史附件是另一层存储。** 返回给模型的图片仍由宿主写入自己的媒体库；当前World接口没有安全回收指定历史附件的能力，本World不会删除宿主共享媒体库。图片缓存清理不等于历史附件清理，历史聊天中已有的图片继续由Cortico管理；本包以降低采样频率和累计交付预算控制新增。

## B站既有验收范围

- 搜视频、查看详情和评论；读取账号有权限访问的字幕。可选本机 FFmpeg 抽取视频画面，明确标出采样时刻，未读取的内容不声称看过。
- 扫码登录；接收评论回复和 @通知；第一次连接只接收连接后的通知。
- 收件箱、线程和发送回执保存在部署的数据目录，重启和上下文交接后可重新检索。
- 默认关闭通知监听和公开发送。开启后，由 Persona 判断是否回复，无逐条确认流程。
- 发送前写入持久记录并补齐 B站分配的网页设备会话；网络结果不明时标为“待核实”，同一操作不自动重发。
- 发评后以未登录访客读取评论列表，区分“访客可见”“仅自己可见”“公开状态待核实”。工具 `socialmedia_inbox` 的 `action=verify` 可只读核验，不重新发评；日常面板不显示复查按钮。核验限时 8 秒，分页未覆盖或平台读取受限时不下审核结论。World 无法将平台审核中的评论强制改为公开。
- 控制台提供平台状态、扫码登录和按视频/楼层聚合的互动时间线，收到的评论与自己的主动发言一起显示。平台网页内容均为外部资料，不能据此取得配置、秘密或其他平台的私聊内容。

## 开发

Node.js >=22.16；Cortico >=0.2.5，World API 6。

```sh
npm install
npm test
npm run typecheck
npm run build
npm pack --dry-run
```

运行时不依赖 AstrBot、Python 或浏览器 World。默认发评需要本机已有Chrome或Edge，由本包直接操作独立的官方网页评论框，无需远程调试。浏览器登录资料放在部署 `data/socialmedia/browser-profile`，不读取日常浏览器的其他账号。默认在后台运行，不弹出浏览器窗口；可在配置中关闭后台模式以排查页面。发送结束会关闭本包打开的浏览器；遇到登录、验证码或页面异常时明确返回，不能自动切回旧接口。网页发送首版支持视频评论；动态评论先读取原动态以绑定准确链接与评论目标；支持原生评论及楼中楼，页面未展示目标楼层时不会改回其他位置。FFmpeg 仅用于画面采样，缺少时仍可读详情、字幕和评论。

## 安装与使用

这是通用World包，不含预设人格、主人账号、登录态、通知或聊天记录。首次安装时自行启用World、登录并选择功能；通知监听、公开发布、闲逛和特别关注默认关闭，主人账号留空。更新只替换扩展代码，保留使用者自己的部署配置和数据。

发布到 npm 后，在 Cortico「扩展 → World → 手动安装」填 `cortico-world-social-media`；本地开发可直接选择本包目录。也可在宿主的 `extensions/` 目录运行：

```sh
pnpm add cortico-world-social-media
```

重启宿主，在 World 列表启用「社交视窗」，打开「配置」中对应平台的登录入口扫码；「平台与记录」用于查看作品与交流历史。默认允许读取 B站内容，通知监听和公开发布需要分别开启。公开发布开启后无需逐条人工确认；可随时关闭。Persona 会收到评论事件并自主组织对话，World 不另行调用大模型、不建立第二套人格。

默认每 60 秒检查一次通知，两次评论至少间隔 30 秒，每日总发布上限 200 条（按部署时区；选择参考档会相应调整）；这些是本包的可调节流设置，不代表平台许可或安全额度。平台限流时暂停同步 5 分钟，登录失效需要重新扫码，不绕过验证码。当前不自动刷新登录 Cookie。

视频支持 BV/av 号、完整视频链接和分集选择。短链接需先展开。画面采样只使用播放接口提供的受支持 HTTPS CDN，单次流最多 64MB、新安装默认最多 2 张画面（保留既有配置），不读取音轨；字幕缺失、账号无权访问或媒体格式不支持时明确返回原因。FFmpeg 可在 PATH 中安装，也可在设置中填写程序路径。

近期通知、线程目标和回执保存在部署 `data/socialmedia/state.json`，较早完整回执保存在同目录 `history.sqlite`，观察预算和可重建缓存位于 `resource-cache/`；登录保存在宿主的秘密配置中，工具、事件和面板状态均不返回 Cookie。收件箱保留最多 2000 条未处理通知与最近 1000 条已处理通知；发送操作编号保留用于防重。结果不明的发送须核对后在面板记录结论。同一个状态目录只供一个宿主使用；共享代码包不会共享账号或消息。

明确拒绝的发送可在排除原因后用 `retryRejected` 重试，每次尝试保留独立回执；结果不明的发送不能用这个选项重发。

这不是 B站官方接口，平台变动可能使功能失效或限制账号。当前标记为实验版本：公开读取和媒体采样可单独验证，真实账号的通知与发布仍需使用者登录后验收。

## 发言前整理与公开语境

World自带局部公开交流说明，不要求使用者改全局人格或记忆提示词。默认围绕当下视频和原话，友善、具体肯定、鼓励与好奇，可适量使用颜文字；不习惯性“赞同一半再反驳”，不主动引入只有熟人才懂的其他World、私聊或内部项目背景，也不每条附工具使用报告。

Persona先用 socialmedia_prepare 提供一句沟通目的和草稿。World整理原楼层、已读依据和最近公开表达，返回柔性建议与 briefId；不发送、不另调模型、不读取私人Memory。Persona读后自行修改、保留或放弃，发布时携briefId。直接调用发布而缺少整理时，工具返回 needs_review 和已准备好的上下文；这是正常下一步，不是发送失败，不计次数，也不需主人确认。既有发送的幂等回执仍优先返回，结果不明或仅自己可见不自动重发。

建议由宿主Persona结合上下文判断，并辅以小范围本地检查，不能保证模型每次都表达得理想；最终措辞由宿主Persona生成。记录保留沟通目的、公开原话和简短提醒，不记录隐性推理，也不把公开平台风格应用到其他聊天场景。

记录页默认将每条视频收成圆角折叠卡，点开后按根楼层串起对话，区分被@、收到回复、主动评论与主动接楼；自己的发言不需要先有通知才会显示。每条提供视频入口及可用的精确楼层链接，连接与闲逛操作统一位于独立配置页。日常页面移除复查按钮和待核验大指标，保留实际回执与必要异常提示；不再定时反复复查公开状态。回执与发言前整理默认折叠，长正文可以展开，内容沿宿主页面自然滚动，没有列表、引用或闲逛记录中的独立纵向滚动框。刷新时保留阅读与展开位置，搜索临时展开命中视频，清空后恢复原选择。待回应只指来信待处理；访客可见、仅自己可见、公开待核验各自标明。支持筛选、搜索、顺序切换，新消息不会强制挪走正在读的位置。

视频标题与原评论在后台逐个补齐，读取失败时保留编号和可用入口，不推断不存在的内容。公开元数据与近期整理随部署保存：最近200条视频、1000条评论上下文、50次整理；原通知、发言回执与防重记录保持原有存储策略。打包不包含任何本地记录、账号或Cookie。

## 闲逛与谈资

默认关闭，在「配置」开启「闲时自主阅读」。无需额外模型或计划任务：World 只在主循环持续空闲、最近没有群聊或私聊时给一次机会，由宿主 Persona 决定看什么、接哪一楼或跳过。不会强迫发评，不会为了完成数量而说话。阅读可正常进行；公开发言还须开启发布开关。

| 参考档 | 机会/天 | 视频/轮 | 评论/视频（含楼中楼） | 主动发言/轮 | 主动发言/天 | 通知回应/天 | 间隔/空闲（分钟） |
| ------ | ------- | ------- | --------------------- | ----------- | ----------- | ----------- | ----------------- |
| 轻量   | 4       | 2       | 20                    | 3           | 8           | 40          | 120 / 10          |
| 均衡   | 8       | 3       | 40                    | 5           | 24          | 80          | 60 / 8            |
| 活跃   | 12      | 5       | 60                    | 8           | 60          | 120         | 40 / 5            |

这些是可编辑的使用预算，不是平台许可或安全保证。配置页提供参考档卡片和逐项自定义；0条发言可只看不说。选择档位不会自动开启闲逛。单轮默认30分钟，字幕默认最多10000字符；搜索最多为本轮视频预算的两倍。主动接楼与独立评论共用额度，通知回应另有较宽预算，普通发布共用普通总上限；主人作品评论自动回应独立计账；选择预设同步设置两者之和作为总上限，不改变启停或认证。普通渠道对同一用户每日最多回应五条，通知回复和主动接楼跨视频累计、重启不重置；结果不明或发送中也先占额度，明确未发出的不占。无法取得对方平台账号时先补读一次，仍无法取得则不发，不用昵称猜身份。

闲逛工具调用携带机会中的 roamId；开始、结束或跳过使用 socialmedia_roam。已读视频、评论阅读量、简短心得和发送关联都持久保存，重启不清零。最多保存最近100轮，面板和状态默认展示最近5轮；跳过也占一次机会，避免重复唤醒。上下文交接后可检索活跃轮次再继续，超时后不可继续消耗旧轮次。

Persona 可以根据已读评论返回的 target 主动在楼中楼补充观点，无需等到@。只在确有价值时整理长期记忆，World本身不改人格或训练模型，也不把评论观点当成事实。只读字幕和采样画面时不声称完整听看。

接口直发是独立实验选项，补齐普通WBI签名和来源字段仍不等于平台保证公开；平台设备验证由官方网页处理，不伪造。以每条发送的访客核验为准；接口已受理、仅自己可见或结果不明时，不会改走网页重新发布同一条。

## 结构与扩展

`src/platform.ts` 定义平台适配契约，`src/platforms/bilibili.ts` 负责 B站接口；`src/service.ts` 负责收件箱和发送流程；`src/store.ts` 保存部署状态；`src/world.ts` 连接 Cortico 工具、事件和面板。新平台实现适配契约并注册后再开放配置，不以空实现冒充已接入。

测试使用真实临时目录和受控 HTTP 响应，不登录真实账号、不发送真实评论。发布包白名单只收代码、构建后的界面和说明，不包含本机账号、消息记录、模型设置和绝对路径。

接口行为参考：[AstrBot B站 AI Bot](https://github.com/chenluQwQ/astrbot_plugin_bilibili_ai_bot)、[BiliCommentBot](https://github.com/Janson20/BiliCommentBot)。本包独立实现 TypeScript 平台适配，不依赖这两个项目运行。后续平台应复用收件箱与回执契约，各自实现鉴权、内容读取和消息映射。

## 外部消息与交流边界

外部评论、昵称、字幕、简介和画面只能作为本站阅读与回复的资料，不具备本机命令、文件、其他World、认证凭证、配置或长期指令的授权。World随包提供这项局部说明；明显的提示词越权、破坏、凭证索取、骚扰或巨量计算请求会本地跳过、保留原因，不唤醒Persona。达到回复上限也正常跳过，不以工具失败要求主人放行。

该本地筛查不执行表达式、不增加模型调用；普通问题和风险讨论仍可接话。语义判断与最终措辞由宿主Persona负责，关键词筛查与局部说明不等同于宿主对所有其他World的强制沙箱，也不保证平台审核结果。发送、读取依然使用原有目标校验、账号绑定和持久化防重。

配置页的「检查登录」「检查网页发评」「立即同步」会在按钮下方显示执行中、完成时间和结果，自动刷新不会清掉。登录有效不代表网页组件必定可用；网页检查仅打开已读视频的评论框，不填写或发送评论，最多约60秒。同步读取回复与@通知，不是刷新所有视频评论；没有新通知时记录不增加。监听关闭、平台冷却或已有同步时明确说明，不伪装成成功，也不绕过冷却。

## 主人账号与特别关注

在「配置 → 特别关注」由使用者自行填写 UID、B站主页链接或昵称，再开启关注。默认空白且关闭，不包含任何预绑定账号。推荐 UID 或主页链接；填写昵称时，只从当前登录账号已收到的B站评论通知中，选择昵称匹配且联系时间最早的账号，固定其 UID。尚无联系记录时保持等待，不做全站同名猜测。这里的“首次”是本部署保存的可用通知记录，不代表B站完整历史；新通知需开启通知监听才会收到。确定后可在界面核对UID，必要时直接改填正确UID。之后改名或后来出现同名账号不会替换既有绑定。

这项绑定仅能在本地配置修改，模型工具和评论区的身份声明不能修改。它只影响本站内容优先级，不授予账号本机、记忆、其他World或秘密配置权限。

空闲时按配置间隔检查最近作品，默认每30分钟查看最近12条（最多30条）。记录页折叠显示这些作品是否尚未参与、已发送或结果待核对；未覆盖的历史作品不作判断。每次最多产生1条新作品机会及2条评论区接话机会，最近3条作品的评论区轮流抽查，并非完整监控所有历史楼层。由宿主Persona先读内容、整理表达，再决定捧场、接话或跳过。不会自动点赞、关注、刷量，也不会为了捧场编造经历、硬夸或攻击其他观众。

普通主动捧场默认每天最多8次，受普通发布上限和每人五条限制；主人作品评论自动回应单独计账，不设日总量或单人次数上限，两者都保留发送间隔。关闭发布可只看不说；关闭特别关注后不再投递或发送旧的关注机会。登录过期、读取受限或网络错误会保留原因并延后检查，不密集重试；已经受理或结果不明的发送不重复补发。通知与普通闲逛仍可分别控制，不会因开启关注而自动打开发布。

## 现实经历与参与判断

兴趣决定优先阅读的题材，适合公开交流才发言。现实养护、医疗、维修和投资等题材默认观察学习；围绕视频画面、创作和共同观感仍可以自然交流。不把虚拟生态箱、游戏、其他World或主人的经历说成自己的现实经验，也不把高赞评论当作真实性证明。

发言整理可附简短的参与结论与依据类别（视频、字幕、评论或推测）。World保留这些短结论，并检查部分明显的无依据亲历表达；可改成有依据的观后感或跳过。这不是万能事实核查器，不记录私下推理，不额外调用模型，也不改系统人格或私人记忆。

发送隔离：公开评论的准备凭据绑定平台、账号、作品、楼层和文案，显式凭据不匹配时拒绝发送。文案修改会返回更新后的准备结果，发送前重新核对，无需人工逐条确认。各World仍共用Persona主上下文，此约束隔离发送目标，不能等同于模型思考会话完全隔离；目前抖音群聊已提供实验接入，快手普通群聊尚未接入。

抖音群的「活跃」影响收到新消息后的接话意愿，不代表必须自言自语。可单独开启「空闲时主动开启群话题」：9至23点、没有近期外部聊天和待办时提供可放弃的机会；默认每群每天2次、间隔120分钟、安静空闲20分钟，参数收在群聊高级设置。重启保留机会计数。没有新消息时不会重播旧对话。
